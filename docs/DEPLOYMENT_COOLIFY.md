# Coolify Deployment Guide — Sharm Pharaoh Travel

## 1. 1-Click GitHub Deployment on Coolify

The repository root [`docker-compose.yml`](../../docker-compose.yml) is pre-configured for **Coolify v4 (Docker Compose Build Pack)**.

### Topology Overview
1. **`postgres` (`postgres:16.4-alpine`)**
   - Internal database on `sharm_internal` (port `5432` never exposed publicly).
   - Backed by persistent volume `postgres_data`.
2. **`migrate` (One-Shot Pre-Start Job)**
   - Runs `pnpm db:migrate:deploy && node scripts/coolify-bootstrap.mjs`.
   - Applies Prisma schema migrations, initializes clean production storefront data (5 destinations, 16 tours, rolling `Africa/Cairo` schedules, published CMS pages + customer-ready `/p/*` legal pages — **zero demo bookings or `.example` addresses**), and provisions the initial `OWNER` user if `INITIAL_ADMIN_PASSWORD` is set.
3. **`api` (NestJS 11 API on `:4000`, non-root `node` user)**
   - Healthcheck: `GET http://127.0.0.1:4000/api/v1/health/ready`.
   - Mounts persistent `public_storage`, `private_storage`, and `backup_storage` volumes.
4. **`worker` (Durable PostgreSQL Outbox Worker)**
   - Processes transactional emails, hold expiry, scheduled CMS publishing, and background translations.
5. **`web` (Next.js 15 App Router SSR on `:3000`)**
   - Dynamically renders storefront/booking/admin routes at runtime (`API_INTERNAL_URL=http://api:4000`) and invalidates cache instantaneously via `/api/internal/revalidate`.
6. **`proxy` (Caddy 2.8 Internal Reverse Proxy on `:80`)**
   - Routes `/api/v1/*` and `/public-media/*` to `api:4000`, and `/*` to `web:3000` on one public origin.
   - Exposes internal port `80` only (`expose: ["80"]`) so Coolify's Traefik reverse proxy terminates HTTPS cleanly without port `80`/`443` collisions.

## 2. Step-by-Step Coolify Setup

1. In Coolify, create a **New Resource -> Public/Private Git Repository**.
2. Set Repository to `https://github.com/Hazemabouseafa/sharm` (`main` branch).
3. Select **Build Pack: Docker Compose** (`docker-compose.yml` at repository root).
4. Open the **`proxy`** service in Coolify and configure your **Domains** field (either your domain like `https://sharmpharaoh.com` or click **Generate Domain** for an automatic `.sslip.io` URL).
   - **Important:** Only the `proxy` service should have a public domain attached (`:80` internal target). Leave `postgres`, `migrate`, `api`, `worker`, and `web` internal without public domains.
5. Add these optional Environment Variables in Coolify before clicking **Deploy** (all database passwords & 64-char security secrets are auto-generated by Coolify via `SERVICE_PASSWORD_*`!):

```dotenv
# Optional: Automatically create the initial OWNER account on first deploy (>= 12 chars)
INITIAL_ADMIN_USERNAME=owner
INITIAL_ADMIN_EMAIL=owner@sharmpharaoh.com
INITIAL_ADMIN_NAME="Sharm Pharaoh Owner"
INITIAL_ADMIN_PASSWORD=<strong-password-12-plus-chars>

# Optional: Explicit canonical site URL (defaults automatically to Coolify SERVICE_URL_PROXY)
PUBLIC_SITE_URL=https://sharmpharaoh.com

# Optional: SMTP for booking confirmations & password resets
SMTP_HOST=
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=
SMTP_PASS=
EMAIL_FROM="Sharm Pharaoh Travel <reservations@sharmpharaoh.com>"

# Optional: Paymob online card checkout
PAYMOB_ENABLED=false
PAYMOB_API_BASE_URL=https://accept.paymob.com
PAYMOB_SECRET_KEY=
PAYMOB_PUBLIC_KEY=
PAYMOB_HMAC_SECRET=
PAYMOB_INTEGRATION_ID=
PAYMOB_CURRENCY=USD
PAYMOB_SANDBOX_VERIFIED=false
```

6. Click **Deploy** and wait for `postgres` -> `migrate` -> `api` & `worker` -> `web` -> `proxy` healthchecks to turn green.

## 3. Creating or Resetting Admin Manually

If you omitted `INITIAL_ADMIN_PASSWORD` during initial setup, open a terminal inside the **`api`** container in Coolify and run:

```bash
node scripts/create-admin.mjs --email owner@sharmpharaoh.com --username owner --name "Sharm Pharaoh Owner" --role OWNER
```

Then sign in at `<your-domain>/admin/login`, enable TOTP 2FA under **Admin -> Settings**, and update your contact phone/WhatsApp/address details in **Settings**.

## 4. Standalone Docker Compose (Non-Coolify VPS)

For standalone servers where Caddy handles TLS directly on ports `80`/`443` without Traefik, use [`infra/compose/docker-compose.prod.yml`](../compose/docker-compose.prod.yml) (production) or [`infra/compose/docker-compose.staging.yml`](../compose/docker-compose.staging.yml) (staging) with explicit `PUBLIC_DOMAIN`, `PUBLIC_SITE_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, and 64-character secrets.
